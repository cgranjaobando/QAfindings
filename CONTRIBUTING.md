# Contribuir a QAFindings

Se aceptan mejoras de método, definiciones, bibliografía, instrumentos, accesibilidad y código, incluidas críticas a las hipótesis. Debe distinguirse opinión, dato observado y evidencia publicada.

**GitHub no es el canal de participación del estudio.** Issues, pull requests y commits muestran cuentas y pueden conservarse en copias. No envíes respuestas, testimonios, empresa, contactos, documentos internos, capturas, audios, transcripciones ni datos de clientes. No solicites que otra persona se identifique.

Para proponer un cambio: explica el problema general, su fundamento, el archivo afectado y el efecto sobre privacidad/medición; usa ejemplos completamente ficticios y etiquetados. No pegues conversaciones reales ni datos antes de anonimizar. Un ejemplo sintético no debe derivarse de una combinación identificable de casos reales.

Revisa el archivo completo antes de modificarlo, conserva comportamientos existentes y ejecuta `python3 -m unittest discover -s tests -v` cuando haya código. Los cambios de ítems requieren actualizar esquema, plan y registro de decisiones. No presentar una escala nueva como validada.

Ninguna contribución marca por sí sola una casilla de aprobación ética. La licencia general de reutilización permanece pendiente conforme a GOVERNANCE.md; los colaboradores deben tener derechos para aportar su material.
