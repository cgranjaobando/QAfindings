# Seguridad y divulgación accidental

**No publiques información sensible para reportar un problema.** El canal privado de investigación todavía no está configurado; no hay recolección activa. No utilices un issue público para adjuntar un archivo o explicar qué persona quedó expuesta.

Antes de campo, el responsable debe habilitar y probar un canal privado, asignar quién responde y definir el procedimiento. No se afirma que GitHub Private Vulnerability Reporting esté activado.

## Si se detecta una exposición

1. Detener la incorporación/publicación de datos afectados y reducir acceso donde sea posible.
2. Evaluar el alcance sin copiar datos a nuevos canales; registrar solo la evidencia mínima necesaria en lugar seguro.
3. Avisar al responsable mediante el canal privado habilitado y evaluar notificación a participantes/autoridades según obligaciones aplicables.
4. Revocar credenciales si corresponde y aplicar eliminación del historial, soporte del proveedor y medidas sobre copias cuando sean posibles.
5. Documentar públicamente una explicación no identificable de lo ocurrido y las medidas cuando sea apropiado.

Eliminar un archivo del último commit no elimina versiones, forks, cachés o copias. .gitignore y pruebas no son controles de acceso. No prometer eliminación total de contenido ya distribuido. La prevención principal es que los datos reales nunca entren al repositorio.
