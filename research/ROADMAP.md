# Hoja de ruta, responsables y recursos

**Propuesta de fases, no compromisos de fechas ni trabajo automático.** No hay tareas programadas ni personas externas contratadas.

| Fase | Producto y criterio de salida | Responsabilidad por asignar |
| --- | --- | --- |
| 0. Constitución | Protocolo público, alcance, registro de decisiones y conflictos | Promotor + revisión metodológica |
| 1. Seguridad y ética | Responsable de datos, canal privado, servicio configurado, evaluación de riesgos y decisión ética documentada | Responsable de datos + revisor independiente |
| 2. Instrumentos | Revisión diversa, entrevistas cognitivas y piloto autorizado; problemas críticos resueltos | Equipo metodológico |
| 3. Congelación | Instrumentos v1, fechas, plan y prerregistro externo verificable | Responsable científico |
| 4. Campo | Ocho semanas propuestas de encuesta; entrevistas separadas; sin mirar resultados para alterar ventana | Coordinación de campo |
| 5. Análisis | Limpieza privada, reglas aplicadas, temas y contraejemplos, matriz integrada | Analista + revisión independiente |
| 6. Divulgación | Revisión de reidentificación y autorización de todo resultado público | Responsable de datos + segundo revisor |
| 7. Manuscrito | Métodos ejecutados, resultados reales, limitaciones y revisión externa | Autores humanos |
| 8. Archivo/cierre | Versión pública identificable, retención cumplida y eliminación registrada | Responsable de datos |

## Recursos necesarios

Tiempo para revisión metodológica, reclutamiento, entrevistas, análisis y escritura; almacenamiento cifrado y respaldo; un canal privado; servicio de encuesta configurado y probado; posibilidad de apoyo ético/jurídico y una persona revisora. Ningún servicio de pago, incentivo o presupuesto está aprobado. Registrar costos reales; no publicar salarios, presupuestos empresariales ni datos privados para justificar financiación.

Si solo participa una persona investigadora, declarar límites de revisión, codificación y separación de funciones. No simular independencia. Antes de abrir debe haber una evaluación externa suficiente del riesgo a participantes, aunque no exista afiliación universitaria.

## Riesgos operativos

- Pocas respuestas o predominio de QA: describir composición y limitar alcance, no fabricar equilibrio.
- Definiciones ambiguas: revisar en piloto y congelar después.
- Exposición o represalias: minimizar, pausar si es necesario, seguir SECURITY.md; no prometer invulnerabilidad.
- Opiniones que condicionen análisis: conservar alternativas y decisiones fechadas.
- Cambios de plataforma o jurisdicción: revisar antes de modificar la recolección.
- Falta de recursos: mantener el proyecto como protocolo sin lanzar una recolección insegura.

## Criterio de éxito

Obtener un estudio ético, trazable y honesto sobre sus límites, independientemente de si apoya o contradice las expectativas iniciales. Número de respuestas, estrellas de GitHub o una conclusión contundente no sustituyen ese criterio.
